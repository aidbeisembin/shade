## Description

Баг с Mac: без доступа к микрофону «Записать» всё равно запускает запись. В неё попадает только звук компьютера, в транскрипте «Thank you.» на 0:00, название из первой фразы. Приложение ничего не говорит.

Вольта в облачной сессии нет, поэтому отчёт здесь. Не сливать.

Живой переключатель на плашке выглядел как настоящий элемент управления, и на него хотелось нажать. Теперь это явная иллюстрация:

## Круг 2: проверка на Mac пропустила запись (коммиты `f74b10a`, `01ac91f`, `9382c38`)

**Что видно:** режим разработки, Терминал сброшен `tccutil`. В онбординге «Позже», затем «Записать». Запись пошла, macOS ничего не спросил, в конце «Речь не распознана».

### Почему проверка пропустила

Гипотеза подтвердилась: сработал оптимистичный путь. В первой версии `checkMicrophone` (`src/aid/lib/mic-access.ts`) порядок был такой:
1. список устройств;
2. команда онбординга `trigger_microphone_permission`;
3. проверка через окно приложения (`getUserMedia`).

Если окно не отвечало «есть» или «нет», итог был `command === true ? 'granted' : 'unknown'`. Команда отвечает `true` всегда, когда поток звука открылся, то есть и при отказе. Онбординг делал то же самое.

Почему окно не ответило именно у вас, по коду установить нельзя. macOS не спросил, значит, `getUserMedia` до системного вопроса не дошёл. Вероятнее всего одно из двух:
- в WebView нет `navigator.mediaDevices`;
- ошибка не `NotAllowedError`.

Журнал теперь пишет:
- есть ли `mediaDevices`;
- защищённая ли страница и какой протокол;
- имя и текст ошибки;
- время ответа.

Строка `[aid] mic перед записью: …` (чек-лист, пункт 9) скажет точно.

### Что изменилось

**Неуверенность нигде не значит «доступ есть».**
- На macOS «да» команды ядра ничего не доказывает, решает окно приложения: «есть», «нет» или «не знаю».
- В онбординге «не знаю» показывается нейтрально: «Проверим при первой записи».
- Перед записью «не знаю» включает страховку.

**Логика доступа:**
- **Доступ не спрашивали:** по «Записать» сразу вопрос macOS, кнопка записи со спиннером.
- **Отказ (на вопрос, раньше или после «Позже»):** запись не стартует, у кнопки записи карточка. «Открыть настройки» ведёт на «Конфиденциальность → Микрофон» (`Privacy_Microphone`). После возврата перепроверка сама:
  - есть: тост «Доступ к микрофону есть, можно записывать»;
  - нет: строка «Уже включили?…»;
  - окно не ответило: тост «Проверим микрофон в первые секунды записи».
- **Пока известно, что доступа нет, кнопка записи «нужен доступ»:** нейтральный круг, перечёркнутый микрофон, без волн. Клик открывает карточку. Отказ запоминается в новом ключе `localStorage` `aid.micAccess.v1`.
- **Страховка, если статус определить не удалось:** первые 3 с окно слушает микрофон:
  - одни цифровые нули: остановка без сохранения, карточка с «Запись не сохранена»;
  - хоть один ненулевой отсчёт: доступ подтверждён.

  Режим «только звук компьютера» страховка не трогает.
- **Слушать микрофон нечем:** во время записи «Не удалось проверить микрофон». Если речи нет, после стопа карточка.

## Круг 1: что было найдено в самом начале

Отказ не видели все три проверки:
- Aid смотрел на список устройств;
- онбординг смотрел на `trigger_microphone_permission`, она отвечает «поток открылся»;
- ядро (`verify_microphone_access`) ждёт первый буфер, а macOS при отказе присылает нули.

Звук компьютера идёт по своему разрешению, поэтому в записи осталась песня. «Thank you.» это галлюцинация Whisper на тишине. Название из первой фразы подставлял наш слой.

## Чек-лист для проверки на Mac (режим разработки)

В `pnpm tauri:dev` разрешение macOS на микрофон спрашивается у **Терминала**, а не у ShadeNotes. Если запускаете из iTerm или VS Code, сбросьте его вместо Терминала.

1. **Сбросить разрешение** Терминала, затем **полностью закрыть Терминал (⌘Q) и открыть снова**:
```bash
tccutil reset Microphone com.apple.Terminal
```
2. **Сбросить запомненный отказ**, если проверяли раньше: в Web Inspector, во вкладке «Console»:
```
localStorage.removeItem('aid.micAccess.v1')
```
3. **Запустить** приложение из Терминала:
```bash
cd frontend && pnpm tauri:dev
```
4. **«Позже» в онбординге.** На шаге «Доступ к звуку» нажать «Позже» и дойти до приложения. Нажать «Записать»: ждём **вопрос macOS**, нажать «Не разрешать». Ждём:
   - карточку «Нет доступа к микрофону» с мини-окном, где указатель включает ShadeNotes;
   - запись не начинается;
   - кнопка записи серая с перечёркнутым микрофоном.

   Если macOS не спросил и запись пошла, через ~3 с она должна остановиться, в карточке строка «Запись не сохранена». Если вместо этого «Не удалось проверить микрофон», пришлите строку журнала из пункта 9.
5. **Кнопка «нужен доступ».** Закрыть карточку, нажать серую кнопку записи: открывается та же карточка. Убедиться, что по мини-окну в карточке не хочется кликнуть, и курсор над ним обычный.
6. **Возврат из настроек.** «Открыть настройки», включить Терминал, вернуться. Ждём: тост «Доступ к микрофону есть, можно записывать», кнопка снова лаймовая. Если строка «Уже включили? Перезапустите ShadeNotes», перезапустить приложение.
7. **Онбординг с отказом** (по желанию, сброс как в пунктах 1–2): «Разрешить» у «Микрофон» → «Не разрешать». Ждём «Доступ закрыт…» и «Открыть настройки».
8. **Только звук компьютера.** Выключить Терминал в настройках, «Записать» → «Только звук компьютера». Включить музыку. Запись идёт, 8 с «Пишу только звук компьютера», без остановок.
9. **Журнал.** В Web Inspector при каждом «Записать» строка вида:
```
[aid] mic перед записью: denied (входов в списке ядра: 1; разрешение macOS через окно: denied (NotAllowedError: … за 12 мс))
```
   Если там `unknown`, пришлите строку целиком: это решит, нужна ли команда ядра.
10. **AirPods, тишина, название:**
    - отключение AirPods даёт тост или «Микрофон отключился»;
    - 30 с тишины дают «Тишина»;
    - «Thank you.» не видно;
    - название «Встреча 7 ноября, 09:40».

В собранном .app (позже) то же, но разрешение у ShadeNotes:
```bash
tccutil reset Microphone io.github.katanana23.aid-meetings
```
